# Contributing

Thanks for contributing to IntentKernel.

## Before Opening a PR

1. Read `README.md` for project scope and status.
2. Review `governance/principles.md`.
3. Keep changes focused and avoid broad unrelated rewrites.
4. Avoid absolute security claims that are not yet evidenced.

## Contribution Types

- Specification clarifications and consistency fixes
- Threat model and invariant improvements
- Reference implementation skeleton improvements
- Tests and tooling that support the documented architecture

## PR Expectations

- Explain what changed and why.
- Note any assumptions, limitations, or unresolved risks.
- Keep terminology aligned with the four-layer stack: IntentKernel, UCCS, IKRL, IBPS.
